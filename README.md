# 房账：个人出租管理 MVP

手机和电脑浏览器使用同一私密站点，使用 ChatGPT 登录。账本按用户隔离保存在 D1；生产环境没有样例数据。

## 功能

- 自有和租入房源；同一套房整租或分租；房源归档。
- 租客及联系方式；出租、上游合同；起止日期、任意押金、1/2/3/6/12 月付款周期、提前支付天数。
- 签约前预览全部租金、押金和固定杂费账单。
- 水、电、网、物业：自行缴纳、手动代收、固定月费；水电支持抄表计费。
- 房源或房间的装修、维修、上游租金及其他成本。
- 部分收付款、退款、同合同押金抵扣、流水冲销；调整或作废未结算账单。
- 提前结束合同并重算自动账单；到期提醒；按房源筛选经营现金收支。
- 完整账本 JSON 和流水 CSV 导出。

## 金额约定

1. 人民币整数分为记账单位，输入字符串解析；抄表数量保留 3 位、单价保留 4 位小数，BigInt 计算后四舍五入至分。
2. 租约月始终从原起租日推算，月末向当月最后一天截断且不累计漂移。结束日期包含当天。不足一个租约月按该租约月实际天数折算，逐月四舍五入，再按付款周期合并。
3. 固定杂费逐月出账并使用相同尾月折算规则。人工调整后的账单不再自动重算。
4. 应收应付不等同于实收实付。只有登记收付款才产生现金流水；退款产生反向现金流水。冲销保留原记录，在冲销日期记反向金额。
5. 收入侧押金余额＝已收－已退－已抵扣；支出侧押金余额＝已付－已收回－已抵扣。收押与付押不进入经营收支。
6. 押金抵扣结清同合同账单，计入抵扣日的经营收支，不增加现金流。现金净额＝经营差额＋租客押金余额－上游押金余额（累计至同一时点）。
7. 经营差额是现金及押金抵扣口径，装修直接计支出，未做折旧、权责发生制或财务利润核算。
8. 不能超收、超退、跨合同抵扣、重复冲销；退款和押金抵扣不能早于实际资金可用日期。账务操作仅允许当前日期及过去日期，使用 Asia/Shanghai 日期。
9. 每次修改带请求编号和账本修订号。重试幂等；不同设备同时修改用数据库原子比较更新，冲突返回最新账本，不覆盖其他修改。

## 验证与开发

使用 `npm install`、`npm run dev`。`npm run db:generate` 生成 Drizzle 迁移。生产由 Sites 应用迁移。

开发 D1：`npx wrangler d1 execute DB --local --persist-to .wrangler/state --config work/local-wrangler.json --file drizzle/0000_magical_emma_frost.sql`。

`node --test tests/ledger.test.mjs` 验证金额与租约边界；`npx tsc --noEmit` 类型检查；`npm run build` 生产构建。

## MVP 边界

手动收付款记录，不对接微信、支付宝或银行。提醒显示在站内，无短信推送。合同保存结构化信息和备注，无合同附件、在线签名。分摊费用手动分配并备注依据。单用户、小规模房源使用，账本单行原子保存，载荷上限 4 MB；目前导出备份，未提供导入覆盖。示例与接口测试只使用本地数据库，不写入生产账本。

WebMCP 提供读取经营概览及打开新增房源表单两项能力，浏览器不支持时忽略；未在支持 WebMCP 的上下文进行运行验证。
